# 阶段 1：视觉样板（第二关）

授权来源：用户要求第一阶段通过后开第二阶段；Codex 已独立复跑阶段 0 自动和浏览器检查，并记录 stage-0-acceptance.md。现在仅执行本阶段，完成后停下等待验收。

## 交付目标

先将 ../UI-REDESIGN-SPEC.md 的设计变成可运行、可截图、可点击的视觉样板。当前并不授权重写完整业务流程。使用真实题库内容，解决排版与空间问题后再接入全部生产页面。

## 实施方式

在 web/ui-preview/ 下制作独立 HTML/CSS/JS 样板，使用现有本地 KaTeX 与题库资源。可从本地题库选择真实章节、选项、长解析、长公式和图片题构造展示，不改题库。不得替换 index.html、legacy.html 或其主业务逻辑，不影响旧版；不要引入 React 或远程依赖。隔离样板不加入生产离线缓存。

入口 web/ui-preview/index.html，提供简单的样板页切换控制（明确属于设计预览，不伪装成功能完成）。各页面沿用设计规定的统一外框、导航、状态栏。样板应适配真实视口，而不是把桌面截图缩小。

## 必须实现的样板

1. 首页：鲜橙继续区约占 2/3，真实章节和题号；右侧复习，近期记录及科目入口。原创建模的括号/上升线品牌标记、统一中文无衬线，鲜橙配深字，安静的灰白外围。演示数据必须标明为预览，不声称是用户真实进度。
2. 题库：256px 内部目录、章节列表、搜索与筛选抽屉；桌面及手机可展开/收起，可看到三个讲师筛选与空结果状态。样板搜索可针对所选样本运行，不宣称全库搜索。
3. 做题：至少一个真实选择题、一个真实长解析/长公式题、一个存在图片资源的真实图片题。支持样本间切题、选择选项、展开/收起解析。阅读面连续，元信息紧凑，收藏/批注/AI 在题干前，稳定底部操作；宽度、字体、行高符合设计。
4. AI 展开：桌面并排 400px，阅读可用宽至少 520px；窄屏转覆盖，手机全屏。使用明确标记的演示对话，包含数学推导、长回复、输入框及三个提示按钮；面板开关、独立滚动、手机返回可实际操作。不要触发真实 AI 请求。
5. 手机导航：关闭/遮罩/选项后收起；键盘焦点可用。展示 390×844 和 360×800 下的题目、AI 输入及操作区，不能产生整页横向溢出。

## 必须消除的现状

中文正文不再使用题册风衬线；不保留巨大淡色题号；答案、解析、视频不再各套灰盒；不是给旧页面盖一层橙色。默认不展示一堆快捷键角标、新旧切换条；版本入口按设计放菜单或设置。正文与 AI 都不能被工具抢占空间。

## 自查与证据

使用 frontend-design 技能进行设计自评、webapp-testing 技能进行真实浏览器检查；按需使用 ui-ux-pro-max，但用户已确认的颜色、字体和布局优先。不要把技能推荐的模板默认值覆盖规格。

截图放 .build/ui-redesign/stage-1/：1440×900 和 390×844 的首页、题库、做题收起/展开、AI 展开；另补 360×800 长公式/图片题。检查页面横溢、按钮遮挡、局部公式滚动、AI/题目独立滚动、焦点、reduced-motion。截图必须来自运行的样板。报告 docs/ui-redesign/stage-1-report.md 列出 URL、样本题 id、文件、设计对应关系、测试及未实现业务边界。
