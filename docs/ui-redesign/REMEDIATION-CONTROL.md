## 关 1：功能兼容和数据可靠性

### 首先保全现场

记录分支、HEAD、状态、未跟踪文件清单。把全部当前改动与未跟踪源码建立可恢复快照，放 `.build/ui-redesign/remediation-1/backup/`，记录快照校验及还原方法；排除凭据和用户学习数据。不得 reset/clean/stash、覆盖旧版、提交合并或推送。随后只在必要范围修改生产代码。

### P0：新旧数据与切换

1. 对照已验证的 `web/app-legacy.js`、`web/ui-version.js` 和服务端 API，列出并对齐每个存储键、数据形状、写入时机。新版目前的 AI 草稿键 `daguan_ai_draft_${qid}` 与共享模块的 `daguan_ai_draft_v1:${qid}` 不同。新版外观键也应使用 `DaguanVersions.appearanceKey`。迁移现存新版草稿/外观数据时只填空白目标键，不覆盖用户已有偏好；可重复执行。
2. 共享收藏、掌握、易错、批注、选题与学习位置。新版的学习位置需与旧版及 `PATCH /api/state/last-study` 协议兼容，使用真实题号/章节，必要写入携带 revision，409 时重新读取后安全重试；显式旧版与公共入口行为继续符合既有契约。不得新增服务端数据迁移或第二套进度。
3. 切换版本、切题、离开批注/学习备忘前先保存本地编辑与必要服务端状态，等待写入完成再导航。任何必要保存失败都保留当前页面和输入并提示可重试。正在生成 AI 时先提示，拒绝则原地继续；确认才停止生成再切换。切换到另一版后恢复同一道题和未发送 AI 草稿，不自动发送。
4. 笔记页切换选中项前保存未提交备忘；保存失败原地保留。同步冲突不可用过时数据覆盖刚写入的收藏和批注。

### P0：AI 接回现有服务

现有 `/api/ai/chat` 接受 `{profileId,question,prompt,includePrivate,images}`，返回 `started/delta/done/error` SSE；新版当前使用 `{messages,apiKey,baseUrl,model}`，不能正常对接。使用现有 `/api/ai/profiles` 档案与共享 `daguan_ai_preferences_v1` 中的 `profileId`，设置页提供现有档案的选择/配置入口，不让用户重新录入一套浏览器凭据。保留最新数学教学约束及“完整解答”快捷提示，以实际请求中发送的 `prompt` 和后端固定 system 指令验证。SSE 正确处理跨块、错误、完成与停止；保留本题聊天历史，切题不串题。支持模拟服务流式验证；真实第三方模型不可用时标明未测。

### P0：工具完整可用

新版组卷、导出、进度备份/恢复、官网同步/预览必须接回旧版已经具备的真实流程，保持预览权限边界。官网同步测试只使用隔离或模拟服务，不写真实官网；若本地服务依赖浏览器扩展等外部条件，至少保留旧版同等的配置与明确入口，不得用“稍后接入”的成功提示替代执行。普通学习备份不得输出 API Key；读取已有备份仍兼容旧格式。备份恢复失败时不覆盖原数据。

### 验收和停止点

保持旧版布局与功能，沿用现有 API/题库格式/题号。完成后将相关新测试加入默认 `npm test`，运行 `npm test`、`npm run verify`、语法检查。用隔离 `DAGUAN_DATA_DIR` 运行 Playwright 真实点击，至少覆盖双向切换与同题恢复、草稿和批注共享、快速切题及保存失败、AI 模拟 SSE/停止/错误、组卷文件、导出文件、备份恢复、同步预览入口与预览权限。桌面 1440×900、手机 390×844 以真实浏览器检查，不靠 `evaluate` 直接调用业务函数代替点击。

产物：`docs/ui-redesign/remediation-1-report.md`，证据 `.build/ui-redesign/remediation-1/`。报告逐项标注实际通过、失败、未测；记录精确修改清单与未解决问题。末尾写“整改关 1 完成，等待 Codex 验收”，然后停止。未通过前不得进入视觉精修。
