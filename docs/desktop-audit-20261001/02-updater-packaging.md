### P1-01 开机启动项指向版本化目录，Squirrel 升级后静默失效

- **证据（代码）** `desktop/electron-main.cjs:183-187`
  ```js
  function setStartup(enabled) {
    startupEnabled = Boolean(enabled);
    app.setLoginItemSettings({
      openAtLogin: startupEnabled,
      path: process.execPath,                       // ← 版本化目录里的真实 exe
      args: app.isPackaged ? [] : [app.getAppPath()],
    });
    buildTrayMenu();
  }
  ```
  配套只读处 `desktop/electron-main.cjs:310`：`startupEnabled = app.getLoginItemSettings().openAtLogin;`（**启动时只读，从不重写登录项**）。
- **证据（官方依据）** `node_modules/electron/electron.d.ts:1781-1784`（`setLoginItemSettings` 文档）：
  > "To work with Electron's `autoUpdater` on Windows, which uses Squirrel, you'll want to set the launch path to your executable's name but a directory up, which is a **stub application automatically generated by Squirrel** which will automatically launch the latest version."
- **证据（目录结构）** `forge.config.js:10` `executableName: "DaguanMath"`、`:44` `name: "DaguanMathDesktop"`；Squirrel 安装布局为 `%LOCALAPPDATA%\DaguanMathDesktop\DaguanMath.exe`（stub）+ `%LOCALAPPDATA%\DaguanMathDesktop\app-<version>\DaguanMath.exe`（真实）。运行时 `process.execPath` 是后者。
- **证据（真实机器上的布局与对比 —— 决定性）** 本机正在运行 v1.0.10 的安装目录（真实路径为 `C:\Users\14666\AppData\Local\Packages\OpenAI.Codex_2p2nqsd0c76g0\LocalCache\Local\DaguanMathDesktop\`，即被 Codex 容器化的 `%LOCALAPPDATA%`）：
  ```
  app-1.0.8/  app-1.0.9/  app-1.0.10/  packages/
  DaguanMath.exe  [347648]     ← stub（Squirrel 生成的执行存根），Test-Path = True
  Update.exe      [1992192]
  app.ico / daguan-logo.ico / Squirrel-*.log
  运行中的 5 个 DaguanMath.exe 进程 ExecutablePath =
    ...\DaguanMathDesktop\app-1.0.10\DaguanMath.exe    ← process.execPath 就是版本化路径
  ```
  而 Squirrel 自己创建快捷方式时用的是 stub（`Squirrel-Shortcut.log`，每次升级都重写）：
  ```
  [01/10/26 05:53:53] About to save shortcut: ...\Start Menu\Programs\Evan26Ma\大观园数学.lnk
    (target ...\DaguanMathDesktop\DaguanMath.exe, workingDir ...\DaguanMathDesktop\app-1.0.10, args , toastActivatorCSLID c01b16b5-...)
  ```

  **对比结论：Squirrel 把快捷方式指向 stub（`...\DaguanMathDesktop\DaguanMath.exe`）并在每次升级时刷新 `workingDir`；而 `electron-main.cjs:185` 把登录项指向 `...\app-1.0.10\DaguanMath.exe` —— 与 Squirrel 自身的约定相反。**
- **状态说明（诚实标注）** 本机 `HKCU\Software\Microsoft\Windows\CurrentVersion\Run` 中**没有**大观园数学条目，说明「开机启动」当前未启用，**因此该缺陷在本机是「潜伏未触发」而非已发生故障**。但布局与对比证据已足以证明：一旦用户勾选开机启动并经历一次升级，登录项就会指向被 Squirrel 删除的目录（`Squirrel-Update.log` 的 `cleanDeadVersions` 会清理非 current/new 的版本目录）。

  ```js
  app.setLoginItemSettings({ openAtLogin: app.getLoginItemSettings().openAtLogin,
    path: app.isPackaged ? stubPath : process.execPath,
    args: app.isPackaged ? [] : [app.getAppPath()] });
  ```
- **验证方式**：新增单测断言 `setStartup` 传入的 `path` 不含 `app-<version>` 段；或安装态实测（勾选→升级→检查 Run 键值→注销重登）。

- **验证方式**：`node -e` 解析 `RELEASES` 并 `crypto.createHash('sha1')` 比对 nupkg；本报告第 3 节已用等价的手工命令跑通并通过。

### P2-01 `stopOwnedServiceForRestart()` 无超时：服务挂起时更新安装永久卡死，托盘被销毁且无任何提示

- **证据** `desktop/electron-main.cjs:201-211`
  ```js
  async function stopOwnedServiceForRestart() {
    if (!ownsService || !serverChild || serverChild.exitCode !== null) return true;
    const child = serverChild;
    return new Promise((resolve) => {
      let settled = false;
      const finish = (result) => { if (settled) return; settled = true; child.off("exit", onExit); resolve(result); };
      const onExit = () => finish(true);
      child.once("exit", onExit);
      try { child.send({ type: "shutdown" }, (error) => { if (error) finish(false); }); }
      catch { finish(false); }
    });
  }
  ```
  **Promise 只有「子进程 exit」和「send 回调报错」两条出路，没有超时。**
- **证据（同一文件里已有正确范式）** `desktop/electron-main.cjs:48-55` `stopStartupChild()` 明确用了 `Promise.race([... , setTimeout(resolve, 5000)])`。**代码库知道这个模式，更新路径偏偏漏了。** 另 `packaging/windows/stop-service.ps1:17-22` 也有 15 秒超时并 `throw "Service did not stop within 15 seconds."`。
- **证据（IPC 通道存在，不会误报）** `desktop/electron-main.cjs:57-58`：`spawn(process.execPath, [SERVER_SCRIPT], { cwd: APP_PATH, windowsHide: true, stdio: ["ignore","pipe","pipe","ipc"], env: {...} })` —— `stdio` 含 `"ipc"`，`child.send` 可用，因此该 Promise 的失败分支只在真正发不出去时才触发；**服务「收到 shutdown 但不退出」时会永久悬挂**。
- **影响链**：`installDownloadedUpdate()`（`:213-231`）在 `:220` `await stopOwnedServiceForRestart()`。若永久悬挂：`:217` 已置 `quitting = true`、`:219` 已 `tray.destroy()`、`:221-227` 的错误弹窗**永不执行**。用户看到的是：托盘图标消失、点击「重启并安装已下载更新」毫无反应、更新永远装不上、也没有任何错误提示；同时 `ipcMain.handle("daguan:update:install")`（`:351`）永不返回，渲染进程的 `await` 也永久挂起。**唯一的恢复手段是强杀进程。**
- **复现**：给 `local-server` 临时加一个忽略 `{type:"shutdown"}` 的开关（例如在 shutdown 分支里 `while(true){}`），打包或开发态运行 → 下载更新 → 点「重启并安装」→ 观察托盘消失且无弹窗。**（本次为只读审查，未实际执行此破坏性实验）**
- **修复建议**：包一层超时，与 `stopStartupChild` 对齐：
  ```js
  const stopped = await Promise.race([
    stopOwnedServiceForRestart(),
    new Promise((resolve) => setTimeout(() => resolve(false), 8000)),
  ]);
  ```
  并考虑超时后额外 `child.kill()` 再等一小段，再决定是否放弃。
- **验证方式**：单测里注入永不 exit 的假 child，断言 8 秒后 `installDownloadedUpdate()` 返回 `false` 且弹出错误框、`quitting` 复位。

### P2-03 更新检查无看门狗：`checking` 悬挂会让更新器永久停摆

- **证据** `desktop/updater.cjs:66-79`
  ```js

    if (!available() || stopped || checking) return false;
    checking = true;
    try { await autoUpdater.checkForUpdates(); return true; }
    catch (error) { checking = false; onState("error"); void log(...); schedule(UPDATE_INTERVAL_MS); return false; }
  ```

  `checking` 只在 `catch`（`:73`）或 `checking-for-update`/`update-available`/`update-not-available`/`update-downloaded`/`error` 五个事件里复位（`:36-63`）。**若 `checkForUpdates()` 返回后既不抛错也不触发任何事件**（例如 `electron-updater` 的 `setFeedURL` 成功但底层 Squirrel 进程卡住、或事件在错误时机被丢弃），`checking` 永远为 `true` → `:67` 的 `if (... || checking) return false;` → **此后所有 `checkNow()`（含托盘「检查更新…」）都直接返回 `false`，`schedule()` 也不再重排（`:33` 的守卫不查 `checking`，但重排只发生在事件回调里，而回调永不触发）→ 自动更新彻底静默停摆，重启应用才恢复。**

### P3-08 发布说明（release notes）在检查更新时必然读取失败，应用永远拿不到 notes（本机实测，影响低）

- **证据** 本机 `Squirrel-CheckForUpdate.log` 在两次「发现新版本」时都记录了同一个异常：
  ```
  [30/09/26 18:15:33] warn: UpdateInfo: Couldn't get release notes for:DaguanMathDesktop-1.0.9-full.nupkg:
    System.IO.FileNotFoundException: 未能找到文件"...\DaguanMathDesktop\packages\DaguanMathDesktop-1.0.9-full.nupkg"。
     在 NuGet.ZipPackage.EnsureManifest()
     在 Squirrel.ReleaseEntry.GetReleaseNotes(String packageDirectory)
     在 Squirrel.UpdateInfo.<FetchReleaseNotes>b__19_0(...)
  [01/10/26 05:52:53] warn: UpdateInfo: Couldn't get release notes for:DaguanMathDesktop-1.0.10-full.nupkg: （同上）
  ```
- **机制**：Squirrel 在 `--checkForUpdate` 阶段就去 `packages\` 目录读**尚未下载**的 nupkg 以提取 release notes，必然 `FileNotFoundException`；Squirrel 把它降级为 warn 并继续，因此**不影响更新本身**（随后 `--update` 正常执行，日志已证明升级成功）。
- **影响**：`update-available` 事件的 `releaseNotes` 永远为空 → 应用无法向用户展示「本次更新改了什么」。当前 `desktop/updater.cjs` 并不使用 `releaseNotes`，所以**实际影响为零**；但若将来想做「更新内容预览」，必须改从 GitHub Release API 取，不能依赖 Squirrel。
- **修复建议**：无需修复。若要做更新说明，从 `https://api.github.com/repos/Evan26Ma/daguan-cxy-local/releases/latest` 的 `body` 读取（本报告已实测该接口可用）。
- **验证方式**：无需验证（日志已直接证明）。

### P3-09 历史日志显示「本地版本高于远端版本」的告警（本机实测，非缺陷，仅记录发布习惯）

- **证据** 本机 `Squirrel-CheckForUpdate.log`：
  ```
  [30/09/26 14:51:12] warn: CheckForUpdateImpl: hwhat, local version is greater than remote version
  ```
  当时本地版本为 `1.0.8`，而 feed 上最新 Release 尚低于 1.0.8（即 v1.0.8 的 Release 尚未发布，本机已先装上了本地构建的 1.0.8）。
