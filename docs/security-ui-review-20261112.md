## 已实施的修复

1. **题图与隐私上下文。** 三个前端题图入口统一使用 `web/ai-question-images.js`，只读取本应用 scheme/host 下哈希命名的栅格题图，拒绝 API、外部地址、重定向和路径逃逸，检查 MIME、签名与读取预算。服务端通过 `local-server/ai-context-policy.mjs` 再校验栅格 data URL、字节数和图片数量。关闭隐私选项后，旧私密轮及可能继承其上下文的旧回复不再发给 AI；本地历史继续保留。
2. **数学表达式资源边界。** 绘图脚本移除 `compile/eval`，采用有节点数、深度、指数与长度限制的数学白名单 AST 解释器，仅进行有限浮点运算。原实现未证实任意代码执行逃逸，确认的问题是字符串乘法及巨大整数幂的资源耗尽边界。
3. **新旧 UI 的 HTML 注入。** 旧版与兼容版筛选项改为 DOM、`textContent`、`dataset`；卡片题号可靠转义，选择器使用 `CSS.escape`。新版题目元数据按文本转义，双引号属性额外转义单双引号，动态回调从 dataset 读取而不拼进 JavaScript 字符串。保留字符串题号。
4. **兼容渲染。** `app2.js` 的 Markdown、HTML、AI 回复和 SVG 使用 `DaguanSafeRender`；缺少清洗依赖时显示转义文本。混淆的可执行链接、事件属性与 SVG 外部引用被移除，KaTeX、原生 MathML、表格和图片查看保留。
5. **QA 健康请求。** `test/squirrel_update_e2e.py` 的端口仅接受 `1–65535` 的严格整数，主机固定为 `127.0.0.1`，健康路径固定。urllib 禁用环境代理与重定向；Playwright 健康请求同样禁止重定向。未运行安装或卸载流程。
6. **本地合并脚本加固。** 两份被 Git 忽略的 `work/lilin-six-v2/merge*.py` 增加 JSON 路径 realpath 目录边界、题库／套号验证、拒绝输出符号链接、独占随机临时文件及原子替换，备份采用独占创建。导入模块不再自动执行合并，读取句柄正确关闭。只在合成目录验证，未执行真实题库合并。这两份本地脚本不强制加入业务提交，另存补丁。

资源引用与 Service Worker 同步到 shell `v178`、新版入口 `v162`、旧版脚本 `v127`、兼容脚本 `v100` 和 AI 模块 `v4`。

## 追加修复：旧历史裁剪后的隐私状态

继续复核发现，旧格式的会话存满 400 条后，最初引入批注的用户消息可能已被裁掉，而后续回复仍可能继承该批注。此前仅靠查找剩余历史中的私密起始轮无法识别这种情况。合成上游的回归测试在修复前确实捕获了批注标记外发。

现在，关闭隐私时，已达历史存储上限的旧记录默认按来源不明的私密上下文处理；只有遇到明确标注 `includePrivate: false` 的新公开轮才恢复回送。未达上限的原有公开历史继续兼容。记录不从本地删除，允许私人上下文时仍可读取原会话。新增真实服务回归验证裁剪后的私密内容连续两轮均不外发，同时新公开回复继续参与下一轮。

在只含暂存候选的隔离工作树中，AI 服务、上下文安全及同步协议共 **17 项全部通过，0 跳过**。包含本日全部暂存修改的最终完整回归为 **423 项：422 通过、1 失败、0 跳过**；唯一失败仍是前述 `2012数二-img` 的原有题号数据问题，与本次修改无关。

## 追加修复：题库同步清单文件路径

复核跨文件链时发现一个可真实利用的写盘边界缺失：`local-server/catalog.mjs` 把官网 `manifest.json` 的 `shards[*].file` 直接交给 `path.join(stagingDir, file)`，并在校验题库总数之前就写入。清单来自网络，带 `../` 的文件名可以把内容写到暂存目录之外，复制阶段还会以同样的相对路径写进 `web/data` 之外；失败时计数校验也不会回滚已写文件。

现在 `catalogTarget()` 在下载与写入前统一解析目标：只接受目录内的相对 `.json` 路径，逐段拒绝空段、`.`、`..`、反斜杠、盘符与冒号、控制字符、Windows 保留名及结尾的点或空格，并对最终 `path.relative` 结果再次确认未越界。清单分片必须是对象；复制阶段同样从校验后的路径出发。

新增 `test/catalog-safety.test.mjs`：单元覆盖 17 种非法拼写；集成测试用合成网络层确认恶意 `../../escaped.json` 在**请求分片之前**即被拒绝、暂存目录外没有产生文件、暂存目录也不残留；合法中文分片名仍能完整同步并正确落位。三项全部通过。

## 提交门禁复核

对已暂存候选重新执行相同深度静态复查，计数仍为 **1 条 direct high、39 条 reachable high、123 条 reachable medium**。其中 39 条 high 与 121 条 medium 均为 `kind: "predict"`、`advisory: true` 的函数名启发式链（如 `fetchJSON`、`buildCard`、`buildCard`→HTML），其“不可信来源”统一写作泛化的“URL 输入”，与真实调用点、参数来源无关；修复真实缺陷不会改变计数，只有改名才会。另 2 条 medium 为 `kind: "crossfile"`，指向 `web/ai-question-images.js` 的 `FileReader.onload` 与浏览器 `fetch`，均为浏览器本地行为。唯一 direct high 仍是测试哨兵。

插件公开命令中，`validate` 仅支持 `path-traversal-read-doc/v1` 与 `command-exec-remote-runner/v1` 两个固定 Oracle，且只接受稳定身份的 direct ledger finding；`backlog`/`ledger` 不产生可供 L3 消费的误报裁定。README 声明“跨文件/预测属告警，只提示不阻断”，但宿主 L3 仍按 40/123 强制拦截。官方仓库 issue [#43](https://github.com/zai-org/zcode-plugins/issues/43) 与 [#63](https://github.com/zai-org/zcode-plugins/issues/63) 已独立复现同一不一致，至今 OPEN 且无维护者回复；当前市场版本 1.0.4 仅修复 Hook stdout 传输，说明中明确签名 payload 未变。因此本项目无法通过受支持命令为这些误报取得放行，也不能用人工 ledger 状态代替。
